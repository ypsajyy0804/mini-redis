## 2. 分层，以及 M1 里唯一一个由我定死的架构决定

```
main.c ──读一行──> 切词 ──> cmd_exec(dict, argc, argv, out, outcap) ──> 打印 out
```

**`cmd_exec` 不碰 stdin，也不碰 socket，不 `printf`。** 它只吃 `argv`，把结果写进调用方给的 `out` 缓冲区。

这是我今天替你定死的唯一一件事，理由是它决定 M2 能不能接上：M2 把 stdin 换成 socket、把文本行换成 RESP 之后，`cmd.c` **一行都不用改**，改的只有 `main.c`。如果你在 `cmd.c` 里写了 `printf`，M2 就得推倒重写命令层。

## 3. 契约：必须存在的声明

```c
/* ---------- dict：从 ht.c 转正 ---------- */
typedef struct Dict Dict;                  /* 不透明：字段只许出现在 dict.c 里 */

Dict       *dict_create(void);
void        dict_free(Dict *d);
int         dict_set(Dict *d, const char *key, const char *val);
const char *dict_get(const Dict *d, const char *key);
int         dict_del(Dict *d, const char *key);

/* ---------- cmd：命令层 ---------- */
#define CMD_OK           0
#define CMD_ERR_ARGS     1
#define CMD_ERR_UNKNOWN  2
#define CMD_ERR_NOMEM    3
#define CMD_ERR_OUTFULL  4

int cmd_exec(Dict *d, int argc, char **argv, char *out, size_t outcap);
```

### 每个签名为什么这样定（这些理由要能自己讲出来）

| 签名 | 为什么 |
|---|---|
| `dict_set` 返回 `int` 不是 `void` | 10-26 的 `vec_resize` 就是 `void` 吞掉 `malloc` 失败。M2 要把 `OOM` 报给客户端，信息不能在这里丢 |
| `dict_get` 返回 `const char *` | 借出去，不拷贝。指向的内存归 dict 所有，调用方不许 `free`、也不许改 |
| `dict_del` 返回 `1` / `0` | 对应真 Redis 的 `DEL` 返回「真正删掉的个数」 |
| `struct Dict` 不透明 | `cmd.c` 碰不到桶数组，扩容逻辑只有 `dict.c` 一处。M2 之后改 dict 不用动命令层 |
| `cmd_exec` 写 `out` 而不是 `printf` | 见第 2 节 |

**`dict_set` 覆盖已有 key 时，必须先 `free` 掉旧的 `val`。** 这是这题真正的内存工作，不是我漏说的细节。

## 4. 命令行为：穷举，一行都不许猜

命令名**不区分大小写**（`set` / `SET` / `SeT` 都是 SET）。key 和 val **原样保留**，不做大小写转换。

| 输入（argv，不含程序名） | 返回 | `out` 内容（逐字，不含换行） |
|---|---|---|
| `SET a 1`（新 key） | `CMD_OK` | `OK` |
| `SET a 2`（已有 key） | `CMD_OK` | `OK`，且旧的 `1` 被释放 |
| `SET a`（argc=2） | `CMD_ERR_ARGS` | `ERR wrong number of arguments for 'set' command` |
| `GET a`（存在） | `CMD_OK` | `1` |
| `GET b`（不存在） | `CMD_OK` | `(nil)` |
| `GET`（argc=1） | `CMD_ERR_ARGS` | `ERR wrong number of arguments for 'get' command` |
| `DEL a`（存在） | `CMD_OK` | `1` |
| `DEL b`（不存在） | `CMD_OK` | `0` |
| `DEL`（argc=1） | `CMD_ERR_ARGS` | `ERR wrong number of arguments for 'del' command` |
| `EXISTS a`（存在） | `CMD_OK` | `1` |
| `EXISTS a`（不存在） | `CMD_OK` | `0` |
| `EXISTS`（argc=1） | `CMD_ERR_ARGS` | `ERR wrong number of arguments for 'exists' command` |
| `FOO`（未知命令） | `CMD_ERR_UNKNOWN` | `ERR unknown command 'FOO'` |
| `FOO a b`（未知命令） | `CMD_ERR_UNKNOWN` | 同上，只打命令名，不打参数 |
| 任何命令，`out` 装不下 | `CMD_ERR_OUTFULL` | 内容未定义，调用方不许读 |

### 切词规则（`main.c` 的责任）

- 用空白切（空格和 `\t` 都算），**连续空白算一个分隔符**
- **不支持引号**：`SET a "hello world"` 会被切成 4 个词，val 是 `"hello`。这是 M1 的已知限制，M2 的 RESP 天然解决
- 空行直接跳过，**不调用 `cmd_exec`、不输出任何东西**
- 读 stdin 到 EOF 退出，退出码 `0`
- **不打印提示符**（`> ` 之类）—— 不然输出没法逐字对

### `main.c` 里读一行用什么

用 `fgets` + 手工切词。**不要用 `scanf("%s")`**：它读到空白就停，没法知道一行到哪结束，也没法给 `argv` 数组定长度。

## 7. M1 明确不做

- ❌ RESP 协议（M2）
- ❌ TCP / 端口 / socket（M2）。M1 的 `main` **不接收任何命令行参数**
- ❌ 持久化（M4）
- ❌ TTL / 过期（M5）
- ❌ 引号、转义、二进制安全的 val（M2 的 RESP 解决）
- ❌ `KEYS` / `SCAN` / `INCR`（M5 或永远不做）
- ❌ 多线程（整个项目都不做，单线程）
